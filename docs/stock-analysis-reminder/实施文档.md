# 股票分析与提醒系统实施文档

## 1. 实施目标

本期目标不是做自动交易，而是在若依 / yudao 现有仓库内完成一个可运行、可扩展、可提醒、可复盘的股票分析系统，完整落地以下链路：

1. 六大短线节点识别
2. 量价关系判断
3. 三重底做T建议
4. 自选股专门采集
5. 提醒发送
6. 图表展示与历史复盘

## 2. 模块边界

- 后端只在 `yudao-module-stock` 内扩展
- 前端只在 `src/api/stock` 与 `src/views/stock` 内扩展
- 不修改 `ruoyi-framework`、`src/framework`、`system` 业务源码
- 股票业务菜单单独归属 `stock`，不混入系统内置 `system` 模块

## 3. 实施顺序

### 3.1 第一步：初始化数据库

执行顺序：

1. `sql/mysql/stock/01_stock_tables.sql`
2. `sql/mysql/stock/02_stock_menu.sql`
3. `sql/mysql/stock/03_stock_seed.sql`

如果使用 mysql 客户端，也可以直接执行：

1. `sql/mysql/stock/00_stock_init.sql`

### 3.2 第二步：启动后端

- 模块已经注册到当前工程
- 本地数据库默认读取 `yudao-server/src/main/resources/application-local.yaml`
- 默认连接库：`ruoyi-vue-pro-jdk8`

### 3.3 第三步：启动前端

- 前端页面已经落到 `src/views/stock/**`
- 菜单依赖数据库动态下发，因此必须先完成菜单 SQL 导入

### 3.4 第四步：验证页面闭环

优先按下面顺序验证：

1. 市场节点页能打开
2. 股票分析页能查询
3. 自选股页能新增监控股票
4. 提醒设置页能看到渠道、规则和记录
5. 历史记录页能查看复盘数据

## 4. 数据源方案

## 4.1 免费优先

- 主源：`Tushare`
- 补源：`AKTools`
- 历史回补：`BaoStock`

这三者的定位不同：

- `Tushare` 适合作为真实数据主链路，而且后续可以平滑升级付费权限
- `AKTools` 更适合作为免费补源，补充市场概览、题材、部分公共数据
- `BaoStock` 更适合补历史数据，不适合作为盘中主链路

## 4.2 付费预留

- `Tushare Pro`
- `JQData`
- `Wind`
- `iFinD`

后续如果你要接更强的数据服务，不需要重做核心规则，只需要新增 Provider 实现并完成 DTO 归一化。

## 4.3 Mock 说明

- `Mock/CSV` 只保留给测试、联调、回放、样例演示
- 生产分析结果不得依赖 Mock
- 如果未来要做自动化测试，可以继续保留 Mock，不影响真实链路

## 5. 针对关注股票的专门采集

系统不是只支持“临时输入代码查一下”，而是支持你关心的股票单独登记与持续跟踪。

支持的能力：

- 加入自选池
- 为每只股票设置采集级别：`NORMAL / KEY / CORE`
- 为每只股票设置采集周期
- 为每只股票单独开启或关闭：
  - 监控
  - 分时采集
  - 做T分析
  - 价格提醒
  - 信号提醒
- 记录最近采集、最近分析、最近提醒和最新建议

这就是“专门采集和登记”的落地点。

## 6. 扩展架构

## 6.1 新方法怎么加

后续如果你还要加其它方法，当前架构是预留好的。

建议扩展方式：

- 新短线节点规则：新增规则实现类，不改原有核心判断链路
- 新量价方法：新增分析实现，不把所有逻辑硬塞到一个 Service
- 新做T方法：新增策略实现类，保留原三步循环做T逻辑
- 新提醒渠道：新增 Sender 实现
- 新数据源：新增 Provider 实现

不建议的方式：

- 直接改框架核心
- 在 Controller 塞大段业务
- 在一个 Service 里用 if/else 把所有方法越堆越大

## 6.2 当前预留点

- 数据源扩展点：`StockDataProvider`
- 提醒扩展点：`StockAlertSender`
- 配置扩展点：`stock_analysis_config`
- 页面扩展点：`src/views/stock` 下新增独立页面
