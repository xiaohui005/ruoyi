# 股票模块前端页面说明

## 1. 页面总入口

股票模块一级菜单为“股票分析”，包含六个页面：

1. 市场节点
2. 股票分析
3. 行情监控
4. 自选股监控
5. 提醒设置
6. 历史记录

数据库菜单组件路径如下：

- `stock/market-signal/index`
- `stock/analyzer/index`
- `stock/monitor/index`
- `stock/watchlist/index`
- `stock/alert/index`
- `stock/history/index`

## 2. 页面展示逻辑

系统前端展示顺序不是乱放的，而是固定围绕你的实战逻辑展开：

1. 先展示“当前市场能不能交易”
2. 再展示“这个股票量价结构是否成立”
3. 最后展示“做T价位、仓位和失效条件”

## 3. 市场节点页

用途：

- 展示当前是否处于六大短线节点之一
- 展示节点触发原因
- 展示市场快照，例如涨停数、跌停数、上涨下跌家数、指数变化、热点题材
- 展示节点历史记录

你打开这个页面，首先看到的是“当前市场节点卡片”，它相当于整套系统的交易入口判断。

## 4. 股票分析页

用途：

- 输入股票代码后得到单股分析结果
- 把“市场节点 -> 量价关系 -> 做T结构”完整串起来
- 支持一键把分析标的加入自选股监控

页面内容包括：

- 市场节点
- 量价关系
- 股价位置
- 综合建议
- 风险等级
- 支撑位、压力位
- 买入区间、卖出区间
- 仓位建议
- 失效条件
- 推理链路

这个页面是最核心的“看结论 + 看原因”页面。

## 5. 行情监控页

用途：

- 展示某只股票的 K 线与成交量
- 在图上叠加支撑位、压力位、做T点、提醒点
- 辅助你肉眼复核系统建议

页面会展示：

- 顶部摘要卡片
- ECharts K 线图
- 成交量柱状图
- 下方 K 线明细表

这个页面不是单纯看图，而是把规则结论落到图上，帮助你确认“为什么这个位置可以低吸或减仓”。

## 6. 自选股监控页

用途：

- 管理你重点关注的股票
- 为每只股票配置专门采集和提醒策略
- 查看每只股票最近分析、最近提醒和最新建议

页面支持：

- 按代码或名称检索
- 启用 / 停用监控
- 配置采集级别与采集周期
- 开关做T分析、价格提醒、信号提醒
- 查看运行状态

这个页面对应你问的“有没有针对我关注的股票进行专门采集和登记”，答案就是这里。

## 7. 提醒设置页

用途：

- 管理提醒渠道
- 管理提醒规则
- 查看提醒记录
- 调整分析阈值配置

页面分四个标签页：

- 提醒渠道
- 提醒规则
- 提醒记录
- 分析配置

这样设计的好处是：渠道、规则、执行记录、参数都能在一个地方闭环处理。

## 8. 历史记录页

用途：

- 管理交易复盘记录
- 对照系统建议和你的实际执行
- 便于后续持续优化策略

页面字段包括：

- 买入价
- 卖出价
- 仓位比例
- 收益率
- 系统建议
- 交易时间
- 备注

## 9. 为什么你之前“没看到前端”

根因通常有两个：

1. 页面源码已经有了，但数据库里没有股票模块菜单
2. 菜单有了，但当前角色没有分配股票菜单权限

本次已经把这两个问题都处理到初始化 SQL 里：

- `02_stock_menu.sql` 写入菜单
- 同时给 `super_admin` 角色写入菜单授权

## 10. 后续怎么扩页面

如果后续你要增加其它方法对应的新页面，建议保持现有规则：

- 新页面继续放 `src/views/stock/新页面`
- 新接口继续放 `src/api/stock/新页面`
- 菜单继续写到 `sql/mysql/stock/02_stock_menu.sql`
- 权限继续用 `v-hasPermi`
- 页面内不要直接写 request，统一走 api 文件

这样扩展才不会把股票模块越做越乱。
