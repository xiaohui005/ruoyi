# 建议闭环与准确率统计方案

## 1. 背景

当前系统已经具备以下能力：

- 能输出股票分析结论
- 能输出 `BUY`、`T_STRATEGY`、`WAIT` 等建议动作
- 能记录分析快照、做T价位、提醒发送记录
- 能手工录入交易复盘

但当前还缺少一层关键闭环：

- 系统给出了一轮建议后，没有持续跟踪这轮建议后续是否达标
- 没有自动判断这轮建议最终是成功、失败、失效还是超时
- 没有把这些结果汇总成命中率、准确率、平均收益率等统计指标

这会导致一个实际问题：

- 用户能看到“现在建议买入”或“现在适合做T”
- 但过几天后，系统无法明确告诉用户“这轮建议后来表现怎么样”
- 也无法回答“系统最近 30 次建议到底准不准”

## 2. 本次目标

本次方案的目标不是改分析算法，而是在现有分析能力之上，补齐“建议闭环评估”。

补齐后，系统应具备：

- 对每一轮建议建立独立记录
- 持续跟踪该建议后续是否触发买点、卖点、失效条件
- 自动给出这轮建议的最终结果
- 在页面上展示该建议是否达标
- 统计不同建议类型的命中率、成功率、失效率、平均收益

## 3. 当前系统现状

### 3.1 已有记录

当前系统已经有以下表或记录能力：

- `stock_analysis_record`
  - 保存每次分析的市场节点、量价结论、建议动作、风险说明
- `stock_t_strategy_record`
  - 保存每次做T分析对应的支撑位、压力位、买卖区间、失效条件、建议仓位
- `stock_alert_record`
  - 保存提醒是否触发、是否发送成功
- `stock_trade_journal`
  - 保存用户手工录入的买价、卖价、收益率、复盘备注

### 3.2 当前缺口

当前缺少的是“建议生命周期表”。

也就是说，系统现在只有“某一时刻给了什么建议”，没有“这条建议后来怎么样了”的专门记录。

## 4. 核心设计思路

新增一张“建议闭环表”，把每次值得跟踪的建议单独存起来，并持续更新它的生命周期状态。

建议闭环的对象包括：

- `BUY`
- `T_STRATEGY`

默认不对 `WAIT` 建议做闭环统计，因为它本身更偏观察，不适合作为明确交易建议统计准确率。

## 5. 建议闭环生命周期

### 5.1 建议创建时机

当系统分析结果满足以下条件之一时，创建一条建议闭环记录：

- 建议动作为 `BUY`
- 建议动作为 `T_STRATEGY`

创建时，把当时的关键快照一并固化：

- 分析记录 ID
- 股票代码、名称
- 建议类型
- 建议生成时间
- 当时最新价
- 支撑位、压力位
- 买入区间
- 卖出区间
- 建议仓位
- 失效条件
- 风险等级

### 5.2 生命周期状态

建议统一使用以下状态：

- `PENDING`
  - 待观察，建议已生成，尚未命中任何条件
- `BUY_TRIGGERED`
  - 已触发买点
- `SELL_TRIGGERED`
  - 已触发卖点
- `INVALIDATED`
  - 已失效，例如跌破关键支撑或结构被破坏
- `COMPLETED`
  - 已完成，这轮建议已达到预设目标，可计入成功
- `EXPIRED`
  - 已超时，观察窗口结束仍未完成
- `MANUAL_CLOSED`
  - 用户手工关闭，例如用户认为这轮建议不再跟踪

### 5.3 状态流转规则

建议状态流转规则如下：

1. 新建议创建后，初始状态为 `PENDING`
2. 当价格进入建议买入区间时，更新为 `BUY_TRIGGERED`
3. 当价格进入建议卖出区间时：
   - 如果是 `BUY` 建议，可直接视为 `COMPLETED`
   - 如果是 `T_STRATEGY` 建议，只有在先经过买点后再触发卖点，才视为 `COMPLETED`
4. 当价格触发失效条件时，更新为 `INVALIDATED`
5. 当超过设定观察周期仍未完成时，更新为 `EXPIRED`
6. 用户可以在后台手工关闭，更新为 `MANUAL_CLOSED`

## 6. 达标判定规则

### 6.1 BUY 建议

`BUY` 建议主要回答两个问题：

- 价格有没有进入建议买入区间
- 买入后有没有达到预期卖出区间或目标收益

建议规则：

- 命中买入区间：记为“已触发”
- 后续达到卖出区间：记为“成功完成”
- 先触发失效条件：记为“失败失效”
- 超过观察周期仍未到买点或目标：记为“超时未完成”

### 6.2 T_STRATEGY 建议

`T_STRATEGY` 建议更强调一轮完整做T闭环。

建议规则：

- 价格进入买入区间：记为“已触发买点”
- 在未失效前进入卖出区间：记为“成功完成”
- 在买点之前或之后触发失效条件：记为“失败失效”
- 超时未走完整个买卖流程：记为“超时未完成”

## 7. 建议准确率口径

为了避免统计口径混乱，需要提前定义指标。

### 7.1 建议总数

统计周期内进入闭环表的建议数。

### 7.2 有效建议数

排除以下情况后的建议数：

- 用户手工关闭
- 数据缺失导致无法评估

### 7.3 成功率

`COMPLETED / 有效建议数`

### 7.4 失效率

`INVALIDATED / 有效建议数`

### 7.5 超时率

`EXPIRED / 有效建议数`

### 7.6 买点触发率

`BUY_TRIGGERED 或已完成 / 有效建议数`

### 7.7 平均收益率

优先取实际交易复盘中的收益率；

如果用户没有录交易复盘，可先按系统规则估算：

- 以买入区间中位价作为理论买入价
- 以卖出区间中位价作为理论卖出价
- 计算理论收益率

后续在页面上需要明确区分：

- `实际收益率`
- `理论收益率`

## 8. 数据库设计建议

建议字段如下：

- `id`

- `watchlist_id`
- `analysis_record_id`
- `symbol`
- `stock_name`
- `advice_type`
  - `BUY`
  - `T_STRATEGY`

  - `PENDING`
  - `BUY_TRIGGERED`
  - `SELL_TRIGGERED`
  - `INVALIDATED`
  - `COMPLETED`
  - `EXPIRED`
  - `MANUAL_CLOSED`

- `latest_price_at_advice`

- `sell_low_price`

- 方便后续审计和复盘

## 9. 后端实现建议

### 9.1 建议创建

在分析结果落库后：

- 如果 `adviceAction` 是 `BUY` 或 `T_STRATEGY`
- 自动创建或刷新一条建议闭环记录

这里建议加“去重策略”：

- 同一只股票
- 同一建议类型
- 同一用户
- 同一交易日

默认只保留一条活跃建议，避免同一天重复生成多条近似记录。

### 9.2 自动评估任务

建议新增一个定时任务：

- 扫描所有状态为 `PENDING`、`BUY_TRIGGERED`、`SELL_TRIGGERED` 的活跃建议
- 读取最新行情
- 按规则更新建议状态
- 记录状态变更日志

### 9.3 与交易复盘联动

当用户在“历史记录/交易复盘”里手工录入交易时：

- 可让用户选择关联某条建议闭环记录
- 自动回填实际买价、卖价、实际收益率
- 优先以实际收益作为准确率统计依据

## 10. 前端页面建议

### 10.1 推荐页

推荐页增加以下字段：

- 本轮状态
- 建议时间
- 是否已达标
- 是否已失效
- 预计观察天数

### 10.2 自选股页

自选股页增加以下字段：

- 当前活跃建议类型
- 当前活跃建议状态
- 最近一次建议结果
- 最近一次完成收益

### 10.3 历史记录页

历史记录页建议拆成三个页签：

- 分析记录
- 提醒记录
- 建议闭环记录

建议闭环记录页要显示：

- 股票代码
- 建议类型
- 建议生成时间
- 买入区间
- 卖出区间
- 当前状态
- 最终结果
- 理论收益率
- 实际收益率
- 结果说明

### 10.4 统计看板

建议新增一个“策略统计”区域，展示：

- 最近 7 天成功率
- 最近 30 天成功率
- `BUY` 建议成功率
- `T_STRATEGY` 建议成功率
- 平均理论收益率
- 平均实际收益率
- 失效率
- 超时率

## 11. 执行顺序建议

建议分三期做，避免一次改太大。

### 第一期：打通闭环主链路

目标：

- 新增建议闭环表
- 分析后自动生成建议记录
- 定时任务自动更新状态
- 历史页新增“建议闭环记录”列表

### 第二期：补统计能力

目标：

- 增加成功率、失效率、超时率等统计接口
- 增加统计卡片和筛选条件

### 第三期：补实际收益闭环

目标：

- 交易复盘绑定建议记录
- 区分理论收益和实际收益
- 支持按用户真实交易评估模型有效性

## 12. 本次建议的最小可落地范围

如果你希望先快速上线，建议先做最小版本：

1. 新增 `stock_advice_tracking`
2. 分析结果为 `BUY` 或 `T_STRATEGY` 时自动入库
3. 定时任务更新状态为：
   - `PENDING`
   - `BUY_TRIGGERED`
   - `COMPLETED`
   - `INVALIDATED`
   - `EXPIRED`
4. 历史页增加“建议闭环记录”
5. 增加成功率、失效率两个统计指标

这样就已经能回答两个最关键问题：

- 这轮建议后来有没有走出来
- 最近系统建议到底准不准

## 13. 需要你确认的业务点

在正式开发前，建议确认以下口径：

1. `BUY` 建议的成功，到底是“进入卖出区间”算成功，还是“达到固定收益率”算成功
2. `T_STRATEGY` 建议的成功，是否必须先到买点再到卖点
3. 观察超时时间按多少天算
4. 是否允许同一只股票同一天存在多条活跃建议
5. 统计口径优先按理论收益，还是优先按实际交易收益

## 14. 结论

当前系统并不是没有记录，而是记录还停留在“分析快照”和“手工复盘”两层。

真正缺的是中间这层：

- 建议创建
- 建议跟踪
- 建议达标判定
- 建议结果统计

把这层补上之后，系统才能从“会给建议”，升级成“能验证建议是否有效”。

这也是后续做推荐页可信度、策略命中率、模型优化的基础。
